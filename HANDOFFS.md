# Owner handoffs

`aoa-models` stops at model knowledge. A handoff must name the source record,
bounded claim, validation already run, validation still required, target
owner, acceptance posture, and rollback or re-entry route.

| Need | Stronger owner | Handoff result |
| --- | --- | --- |
| role, mandate, authority, stop-line | `aoa-agents` | role or summon contract reference |
| routing or incarnation binding | `aoa-sdk` | runtime-neutral binding or projection reference |
| runtime launch, session, resume, receipt | `abyss-stack` | external-process receipt and lifecycle evidence |
| host/resource admission | `abyss-machine` | host policy decision and resource evidence |
| fixture, scoring, comparison, verdict | `aoa-evals` | proof bundle or candidate packet reference |
| choreography and closeout sequence | `aoa-playbooks` | owner-bounded playbook route |
| raw session/execution evidence | `.aoa` | immutable evidence reference |
| derived usage, cost, latency | `aoa-stats` | derived event or summary reference |
| durable recalled knowledge | `aoa-memo` | reviewed intake candidate, never automatic writeback |
| ecosystem registration | `Agents-of-Abyss` | center-owned registry change after owner-local proof |

No handoff transfers acceptance automatically. Rejection or non-admission
returns to the named source record, preserves the evidence, and either weakens
the claim, changes the study, or suspends the consumer projection.
